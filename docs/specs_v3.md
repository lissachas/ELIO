# Спецификация языка

**Цель языка:** быть максимально предсказуемым и безопасным.

## 1. Основные принципы

**Закон безопасности** — поведение программы должно быть явным и проверяемым на этапе компиляции или во время выполнения. Неопределённое поведение отсутствует.

**Закон детерминизма** — одни и те же входные данные всегда дают одинаковый результат. Порядок вычислений строго определён.

**Закон простоты** — каждая конструкция языка имеет единственное очевидное значение. Неявных преобразований нет.

Приоритет: Безопасность >= Детерминизм >> Простота

---

## 2. Лексическая структура

### 2.1. Алфавит и пробельные символы

Исходный файл — последовательность символов UTF-8. Пробел, табуляция, перевод строки служат разделителями токенов и семантики не несут.

### 2.2. Комментарии

Только однострочные. Начинаются с `//`, заканчиваются концом строки. В поток токенов не попадают.

```
// это комментарий
```

### 2.3. Идентификаторы

```
identifier := LETTER (LETTER | DIGIT | '_')*
LETTER     := [a-zA-Z_]
DIGIT      := [0-9]
```

Идентификатор может начинаться с `_`. Ключевые слова не могут использоваться как идентификаторы.

### 2.4. Ключевые слова

```
if  else  while  for  loop  return  match  break  continue  in
fn  struct  let  const  mut
some  none  ok  err
optional  result  shared  weak
sign  unsign  trunc_cast  check_cast  wrap_add  wrap_sub  wrap_mul
true  false
bool  unit
int8  int16  int32  int64
uint8  uint16  uint32  uint64
flo32  flo64
char  string  string_view  buf_string
```

### 2.5. Литералы

**Целочисленный:** одна или более цифр. `42`, `0`, `1000`

**Вещественный:** цифры, точка, цифры. `3.14`, `0.5`

**Строковый:** содержимое в двойных кавычках. `"hello"`. Поддерживаемые escape-последовательности: `\n`, `\t`, `\"`, `\\`.

**Символьный:** содержимое в одинарных кавычках. `'a'`, `'\n'`. Один Unicode scalar value.

**Булев:** `true`, `false`

**Unit:** `none`

### 2.6. Операторы и разделители

```
+   -   *   /   %
==  !=  <   <=  >   >=
=   :=
!   &&  ||
&   *
->  =>
.
:   ;   ,   _
(   )   {   }   [   ]
```

## 3. Структура программы

```
program := item*
item    := function_decl | struct_decl | global_decl | comment
```

На верхнем уровне допускаются только объявления. Инструкции и выражения допустимы только внутри тел функций.

Программа обязана содержать функцию `main`. Точная сигнатура `main` определяется отдельно.

## 4. Типы

### 4.1. Примитивные типы

| Тип | Описание |
|-----|----------|
| `bool` | Логический. Значения: `true`, `false` |
| `unit` | Отсутствие значения. Единственное значение: `none` |
| `int8` `int16` `int32` `int64` | Знаковые целые, 8/16/32/64 бит |
| `uint8` `uint16` `uint32` `uint64` | Беззнаковые целые, 8/16/32/64 бит |
| `flo32` `flo64` | Вещественные числа IEEE 754, 32/64 бит |
| `char` | Unicode scalar value |
| `string` | Неизменяемая строка UTF-8 |
| `string_view` | Заимствованный срез строки без владения |
| `buf_string` | Изменяемая строка UTF-8 |

### 4.2. Составные типы

**Массив фиксированного размера:** `[T; N]`

Размер `N` является частью типа. `[int32; 3]` и `[int32; 4]` — разные типы.

**Ссылки:** `&T` (иммутабельная), `&mut T` (мутабельная)

Временные заимствования для передачи в функции. Ссылки нельзя хранить в структурах или возвращать из функций (в v1).

### 4.3. Параметризованные типы

**`optional[T]`** — значение типа `T` либо его отсутствие.

Конструкторы: `some(expr)`, `none`

**`result[T, E]`** — успешный результат типа `T` либо ошибка типа `E`.

Конструкторы: `ok(expr)`, `err(expr)`

**`shared[T]`** — разделяемое владение объектом через атомарный счётчик ссылок (ARC). Значение живёт пока существует хотя бы один `shared[T]`.

**`weak[T]`** — слабая ссылка на объект под `shared[T]`. Не продлевает жизнь объекта. Используется для разрыва циклических ссылок.

### 4.4. Именованные типы

Идентификатор, соответствующий объявленной структуре. Типизация номинальная: две структуры с одинаковыми полями но разными именами — разные типы.

### 4.5. Совместимость типов

Выражение типа `A` совместимо с контекстом типа `B` только если `A` и `B` совпадают. Неявных приведений нет.

Явные приведения выполняются через встроенные операции (см. раздел 8).

## 5. Объявления

### 5.1. Переменная (`let`)

```
let_decl := pattern ':' type '=' expr ';'
          | pattern ':=' expr ';'
```

Первая форма — явный тип. Вторая форма (`:=`) — вывод типа из инициализатора. Инициализатор обязателен в обоих случаях.

Переменная иммутабельна по умолчанию. Левая часть — паттерн (см. раздел 9).

```
x : int32 = 42;
y := 3.14;
```

### 5.2. Константа (`const`)

```
const_decl := 'const' identifier ':' type '=' expr ';'
```

Значение вычисляется на этапе компиляции. Константа иммутабельна и не может быть переназначена.

```
const MAX : int32 = 100;
```

### 5.3. Функция (`fn`)

```
function_decl := 'fn' identifier '(' param_list? ')' '->' type block
               | 'fn' identifier '(' param_list? ')' '->' type ';'
param_list    := param (',' param)*
param         := identifier ':' type
```

Вторая форма (с `;` вместо тела) — предварительное объявление (forward declaration).

Параметры передаются по значению для примитивных типов. Для остальных используются явные ссылки `&T` или `&mut T`.

```
fn add(a: int32, b: int32) -> int32 {
    return a + b;
}
```

### 5.4. Структура (`struct`)

```
struct_decl      := 'struct' identifier '{' field_decl_list? '}'
field_decl_list  := field_decl (',' field_decl)*
field_decl       := identifier ':' type
```

Структуры являются value types: присваивание создаёт копию всех полей.

```
struct Point { x: int32, y: int32 }
```

Инициализация:

```
p : Point = Point { x: 1, y: 2 };
p2 : Point = Point { x, y };   // сокращённая форма если имена совпадают
```

## 6. Инструкции

```
stmt := let_decl | const_decl | expr_stmt | if_stmt | while_stmt
      | for_stmt | loop_stmt | match_stmt | return_stmt
      | break_stmt | continue_stmt | block | comment
```

### 6.1. Инструкция-выражение

```
expr_stmt := expr ';'
```

### 6.2. Ветвление (`if`)

```
if_stmt := 'if' expr block else_clause?
else_clause := 'else' block | 'else' if_stmt
```

Условие обязано иметь тип `bool`. Неявного приведения к `bool` нет.

```
if x > 0 {
    return x;
} else if x < 0 {
    return -x;
} else {
    return 0;
}
```

### 6.3. Цикл с предусловием (`while`)

```
while_stmt := (identifier ':')? 'while' expr block
```

Условие вычисляется перед каждой итерацией. Тип условия — `bool`. Метка (тег) необязательна.

```
outer: while running {
    while processing {
        break outer;
    }
}
```

### 6.4. Цикл по итератору (`for`)

```
for_stmt := (identifier ':')? 'for' pattern 'in' expr block
```

Выражение после `in` должно быть итерируемым. В v1 поддерживаются массивы фиксированного размера. Левая часть — паттерн.

### 6.5. Бесконечный цикл (`loop`)

```
loop_stmt := (identifier ':')? 'loop' block
```

Выполняется до `break` или `return`. Может возвращать значение через `break expr`.

### 6.6. Возврат из функции (`return`)

```
return_stmt := 'return' ';' | 'return' expr ';'
```

`return` без значения допустим только если тип возврата функции — `unit`.

### 6.7. Выход из цикла (`break`)

```
break_stmt := 'break' ';'
           | 'break' expr ';'
           | 'break' identifier ';'
           | 'break' identifier expr ';'
```

`break expr` возвращает значение из цикла `loop`. `break identifier` выходит из именованного цикла. `break identifier expr` выходит из именованного цикла с возвращаемым значением.

### 6.8. Следующая итерация (`continue`)

```
continue_stmt := 'continue' ';' | 'continue' identifier ';'
```

`continue identifier` переходит к следующей итерации именованного цикла.

### 6.9. Сопоставление с образцом (`match` как инструкция)

```
match_stmt := 'match' expr '{' match_arm* '}'
match_arm  := pattern '=>' (expr ',' | block)
```

Паттерны проверяются сверху вниз. Если ни один не совпал — runtime error.

## 7. Выражения

### 7.1. Приоритет операторов (от низшего к высшему)

| Уровень | Операторы | Ассоциативность |
|---------|-----------|-----------------|
| 1 | присваивание `=` | правая |
| 2 | `\|\|` | левая |
| 3 | `&&` | левая |
| 4 | `==` `!=` | левая |
| 5 | `<` `<=` `>` `>=` | левая |
| 6 | `+` `-` | левая |
| 7 | `*` `/` `%` | левая |
| 8 | унарные `-` `!` `&` `&mut` `*` | правая |
| 9 | постфиксные `()` `[]` `.` | левая |

### 7.2. Арифметические операторы

`+`, `-`, `*`, `/`, `%` — оба операнда обязаны иметь одинаковый тип. Результат того же типа. Неявных приведений нет.

Переполнение целочисленного типа вызывает runtime trap. Деление на ноль вызывает runtime trap.

### 7.3. Логические операторы

`&&` и `||` вычисляются лениво (short-circuit): правый операнд вычисляется только если результат не определён левым. `!` — логическое отрицание. Все операнды обязаны иметь тип `bool`.

### 7.4. Операторы сравнения

`==`, `!=` определены для: всех числовых типов, `bool`, `char`, `string`.

`<`, `<=`, `>`, `>=` определены для: всех числовых типов, `char`, `string`.

Равенство и порядок для структур не определены.

Оба операнда обязаны иметь одинаковый тип.

### 7.5. Присваивание

```
assignment_expr := unary_expr '=' assignment_expr
```

Левая часть (lvalue) — место в памяти, которому можно присвоить значение. Допустимые lvalue:
- локальная переменная (`x = ...`)
- поле структуры (`obj.field = ...`)
- элемент массива (`arr[i] = ...`)
- разыменование мутабельной ссылки (`*ptr = ...`)

Выражения, которые не являются lvalue: литералы, результат вызова функции, арифметические выражения.

Присваивать можно только иммутабельные переменные объявленные через `let` при наличии явного `mut` (поведение `mut` уточняется).

### 7.6. Унарные операторы

| Оператор | Описание |
|----------|----------|
| `-expr` | Унарный минус. Операнд обязан быть числовым |
| `!expr` | Логическое отрицание. Операнд — `bool` |
| `&expr` | Взять иммутабельную ссылку |
| `&mut expr` | Взять мутабельную ссылку |
| `*expr` | Разыменование ссылки |

### 7.7. Постфиксные операторы

**Вызов функции:** `expr(arg1, arg2, ...)`

Аргументы вычисляются слева направо перед вызовом.

**Индексация:** `expr[expr]`

Левый операнд — массив. Индекс — целочисленный тип. Выход за границы вызывает runtime trap.

**Доступ к полю:** `expr.field`

**Вызов метода:** `expr.method(args)` — разворачивается в вызов функции с первым аргументом `expr`.

### 7.8. `if` как выражение

```
if_expr := 'if' expr block 'else' expr
```

Ветка `else` обязательна. Обе ветки обязаны иметь одинаковый тип.

```
x := if flag { 1 } else { 0 };
```

### 7.9. `match` как выражение

```
match_expr := 'match' expr '{' match_arm* '}'
```

Все ветки обязаны возвращать значение одного типа. Если ни один паттерн не совпал — runtime error.

```
result := match opt {
    some(v) => v,
    none => 0,
};
```

### 7.10. Лямбда-функции

```
lambda_expr := '(' param_list? ')' '->' (block | expr ';')
```

Лямбда захватывает переменные из внешней области видимости только иммутабельно и по значению. Изменение внешних переменных изнутри лямбды невозможно.

Короткая форма: `() -> expr;`  
Полная форма: `() -> { return expr; }`

### 7.11. Блок как выражение

```
block_expr := '{' stmt* '}'
```

Блок создаёт новую область видимости. Последнее выражение в блоке (без `;`) является значением блока.

## 8. Явные операции над типами

Все приведения и арифметические операции с нестандартным поведением выполняются явно через встроенные функции. Неявных приведений нет.

| Операция | Синтаксис | Описание |
|----------|-----------|----------|
| Реинтерпретация знака | `sign(expr)` | Беззнаковое -> знаковое, без изменения битов |
| Реинтерпретация знака | `unsign(expr)` | Знаковое -> беззнаковое, без изменения битов |
| Усекающее приведение | `trunc_cast[T](expr)` | Обрезает биты до целевого типа. Не проверяет диапазон |
| Проверяемое приведение | `check_cast[T](expr)` | Приводит к целевому типу. Runtime trap если значение не помещается |
| Оборачивающее сложение | `wrap_add(a, b)` | Сложение с поведением wraparound вместо trap |
| Оборачивающее вычитание | `wrap_sub(a, b)` | Вычитание с поведением wraparound вместо trap |
| Оборачивающее умножение | `wrap_mul(a, b)` | Умножение с поведением wraparound вместо trap |

## 9. Паттерны

Паттерн используется в `let`, `for`, и ветках `match`. Сопоставляет значение с образцом и может вводить новые имена.

```
pattern := '_'
         | 'none' | 'true' | 'false'
         | literal
         | identifier
         | '(' pattern (',' pattern)* ')'
         | identifier '{' field_pattern (',' field_pattern)* '}'
         | 'some' '(' pattern ')'
         | 'ok'   '(' pattern ')'
         | 'err'  '(' pattern ')'
```

| Паттерн | Описание |
|---------|----------|
| `_` | Подстановочный. Совпадает с любым значением. Имя не вводит |
| `none`, `true`, `false` | Литеральный. Совпадает только с соответствующим значением |
| Числовой/строковый литерал | Совпадает если значение равно литералу |
| `x` (идентификатор) | Всегда совпадает. Связывает имя `x` с текущим значением |
| `(a, b)` | Кортежный. Совпадает если каждый вложенный паттерн совпал |
| `Point { x, y }` | Структурный. `x` — сокращение для `x: x` |
| `Point { x: p }` | Структурный с переименованием. Поле `x` связывается с именем `p` |
| `some(p)` | Совпадает если значение — `some`. `p` связывается с внутренним значением |
| `ok(p)` | Совпадает если значение — `ok`. `p` связывается с результатом |
| `err(p)` | Совпадает если значение — `err`. `p` связывается с ошибкой |

Имена, введённые паттерном, доступны только в теле соответствующей ветви.

## 10. Разрешение имён и область видимости

Использует лексическую область видимости.

- Имя разрешается в ближайшей охватывающей области видимости.
- Внутреннее объявление скрывает внешнее (shadowing допускается).
- Повторное объявление одного имени в одной области — ошибка компиляции.
- Использование имени до его объявления — ошибка компиляции.
- Переменная существует с момента объявления до конца блока.

Области видимости создают: тело функции, блок `{ }`, ветвь `match` (если паттерн вводит имена), список параметров функции.

## 11. Семантика вычислений

**Порядок вычисления:** операнды бинарных операторов вычисляются слева направо. Аргументы функции вычисляются слева направо.

**Передача аргументов:** примитивные типы и структуры передаются по значению (копирование). Ссылки `&T` и `&mut T` передаются как заимствования без копирования.

**Value semantics:** присваивание создаёт независимую копию. Изменение копии не влияет на оригинал.

## 12. Модель памяти

### 12.1. Классы хранения

**Стек:** локальные переменные примитивных типов и структур фиксированного размера. Время жизни совпадает с блоком объявления.

**Куча:** динамически размещаемые объекты. Доступ через `shared[T]`.

### 12.2. Владение

Каждый объект на куче имеет ровно одного владельца. Присваивание owned-объекта передаёт владение. Копирование требует явного клонирования.

### 12.3. Заимствование

Функции принимают временные ссылки:
- `&T` — иммутабельное заимствование. Несколько одновременно допустимы.
- `&mut T` — мутабельное заимствование. Только одно одновременно. Не допускается вместе с иммутабельным.

Хранить ссылки в структурах или возвращать их из функций в v1 не допускается.

### 12.4. Детерминированное уничтожение

Owned-значения уничтожаются автоматически в конце области видимости. Порядок уничтожения — обратный порядку объявления.

`shared[T]` уменьшает счётчик ссылок при выходе из области видимости. Когда счётчик достигает нуля — объект уничтожается немедленно.

### 12.5. Разделяемое состояние

Переменные по умолчанию принадлежат одному потоку. Разделение между потоками требует явного `shared[T]` с атомарным счётчиком ссылок.

Циклические ссылки между `shared[T]` необходимо разрывать через `weak[T]`.

## 13. Ошибки компиляции

Компиляция прекращается при обнаружении первой ошибки. Среди обязательно проверяемых:

- лексическая или синтаксическая ошибка
- использование необъявленного имени
- повторное объявление имени в одной области
- использование имени до объявления
- несовместимость типов в выражении
- несовместимые типы ветвей `if`-выражения или `match`-выражения
- присваивание в иммутабельную переменную
- `return` вне тела функции
- `break` или `continue` вне цикла
- использование ключевого слова как идентификатора
- выход за границы массива статически известного размера (если определимо на этапе компиляции)

## 14. Ошибки времени выполнения

Формат: `runtime error: <сообщение> at line <N>`

| Событие | Сообщение |
|---------|-----------|
| Целочисленное переполнение | `integer overflow` |
| Деление на ноль | `division by zero` |
| Выход за границы массива | `index out of bounds` |
| Недопустимое приведение (`check_cast`) | `invalid cast` |
| Неудачный `match` (нет совпавшего паттерна) | `non-exhaustive match` |
